# VideoDNA Changelog

## v2.0.4 — 2026-11-21

Editing-analysis upgrade (all six items of the v2.0.4 plan — per-shot remake material, mixed-production verdict, transition labels, camera motion, rhythm/pacing, on-screen-text OCR). Scope is editing analysis only: no changes to audio.py (v2.0.3 thresholds), the retention formula in diagnostics.py, install.sh, doctor, or the v2.0.2 shot guard.

### Fixed

1. **Per-shot remake frames (item 1) (`videodna/shots.py`, `videodna/cli.py`, `videodna/remake.py`, `videodna/report.py`)** — the remake plan previously had measured per-shot cards but no frames to rebuild from. `export_shot_frames()` now exports first/mid/last JPEGs (480px wide) for EVERY shot into `dna/frames/` (`shot-NN-first.jpg`, `shot-NN-mid.jpg`, `shot-NN-last.jpg`) plus a contact strip (`shot-NN-strip.jpg`, ≤6 evenly spaced frames, shots ≥1s) in ONE ffmpeg streaming decode at ≤30 fps — constant memory, no per-frame ffmpeg spawn. Paths land on each shot dict as `frame_paths` in `blueprint.json` and on both shot-card builders (`remake.build_shot_cards`, `report._build_shot_cards`), and are referenced in `dna/shots.md` and `dna/remake_plan.md`. The existing `frames/shot_NNN_mid.jpg` (visual.py, sampled ≤24 shots) is untouched; the DNA.md file map records both directories so they are not confused. Two edge cases handled: the decode is capped at 30 fps (stills only need ~±16 ms accuracy; measured on speech2 the pass drops 14.1s → 10.1s), and when the container duration runs past the last decodable frame (speech2: container 21.32s, last frame 21.27s) a missing first/mid/last slot is filled by copying the same shot's mid frame — same shot, a fraction of a second away — so the per-shot contract always holds. On any ffmpeg failure the export returns {} and the pipeline continues without frame paths (fail open, like the v2.0.2 guard).
2. **Mixed-production verdict (item 2) (`videodna/forensics.py`)** — the displayed mix is now the duration-weighted MEAN SOFTMAX (`aggregate_mix()`), not winner-take-all, in BOTH `run_shot_forensics()` and `fuse_review_probabilities()` so analyze and apply-review cannot diverge. Rationale: "unknown" is not a production method — it is the per-shot label when no rule fired or the top two classes nearly tied — but winner-take-all dumped all of an unknown shot's duration into that bucket, so speech2 read "unknown 48%" and hid the real live/3D/AI mass. The mean softmax keeps the mass (an unknown shot spreads its near-uniform distribution across the real classes) and preserves minority mass. Trade-off, stated plainly: a video that really is one production method no longer reads a clean "code_motion 100%" — it reads the mean softmax (e.g. U1 code_motion 90% + small softmax residue), because the per-shot classifier is never 100% sure; the per-shot cards (top label + runner-up + confidence) stay the traceable ground truth. `honest_verdict_summary()` now shows the full mix (every label ≥1%) and, below 0.5 confidence, the same full mix suffixed with "— uncertain from pixels alone" with the real runner-up — v2.0.2's short "top / runner_up" form could not name the live share AND the AI/3D share of a mixed video. Overall confidence is unchanged (duration-weighted mean of per-shot confidence) and still gates the qualifier. Per-shot cards now carry `production_runner_up`, `production_runner_up_confidence` and `needs_visual_review` (rendered in `dna/shots.md`, `dna/remake_plan.md`, DNA.md and `report.html`). No new "ai_still" category was added (that touches CATEGORIES, `_score_shot_metrics`, MODEL_CAPABILITIES, `label_alias` and the review template — a later agent may evaluate it; it is NOT required for item 2 because the mix already surfaces the AI share from the existing `ai_video`/`3d_render` classes).
3. **Rhythm/pacing section (item 5) (`videodna/shots.py`, `videodna/report.py`)** — new `rhythm` block in the `detect_shots()` return (flows into `blueprint.json` automatically): shot-length min/median/max with longest/shortest shot identity (shot id + window), cuts per 10s, a shots-per-10s pacing curve (shots starting + cuts per 10s window), and a transitions list (time → into-shot → type; transition duration is NOT measured — only the cut instant is known — so no duration field). Rendered in `dna/shots.md` ("Rhythm & Pacing") and as a one-line summary in DNA.md section 1. Built from the FULL shot list (not the forensics 32/24 or visual 24 caps). Diagnostics retention weights untouched.
4. **Transition labels (item 3) (`videodna/shots.py`)** — every surviving soft transition now gets a `transition_subtype` on the shot dict (`None` for opening/hard cuts): `fade`, `dissolve`, `slide_wipe`, or `soft_unknown`. Runs AFTER the v2.0.2 guard on survivors only, never feeds back into cut decisions; `transition_in` values and cut decisions are unchanged. A fresh window [t−1s, t+1s] is re-decoded at 12 fps / 160px (`_sample_window_frames`, seek-based — the guard's `_sample_frames_at` is untouched). Let A = settled frame before, B = settled frame after, M(τ) = frames through the window. Gate first: the settled frames at t±0.75s must differ across ≥45% of pixels (the guard's own line), else `soft_unknown`. Then in order: (1) **fade** — min mean luma in the window < 0.35 × min(L(A), L(B)), or < 20 (black) / > 235 (white), with recovery on both sides; (2) **dissolve** — per mid frame, scalar α minimising ‖M − (αA + (1−α)B)‖ with residual < 0.5 × ‖M − A‖, α in (0.2, 0.8), for ≥ 3 consecutive mid frames; (3) **slide/push** — ≥ 3 consecutive same-sign axial phase-correlation shifts ≥ 4 px/frame, ≤ 1 px orthogonal, corrected coherence ≥ 0.5, AND the run must displace ≥ half the frame width in total (a slide moves content across the frame; a slow drift does not); (4) **reveal-wipe** (same `slide_wipe` label) — a mid frame is "wipe-clean" only when its 8 strips split into a matched group (mean diff vs B < 8 — the revealed region IS B, near-exact) and an unmatched group (diff > 40), allowing one intermediate boundary strip, with the matched group a prefix or suffix; the wipe-clean matched-counts must grow monotonically through ≥ 4 distinct values, starting ≤ 2 and ending ≥ 5. The sharpness is what separates a reveal from a slow drift/pan into the new layout: a drift's strip diffs form a smooth gradient, so it never produces a wipe-clean frame. Order matters (fade → dissolve → slide → wipe); any disagreement defaults to `soft_unknown`; a subtype is never forced. Subtypes flow into `blueprint.json`, both shot-card builders, the rhythm transitions list (Type cell shows the subtype for soft transitions; hard-cut entries stay exactly `{"time","into_shot","type"}`), and the Transition line of each shot card. Measured ground truth: M3 textured (fade + slideleft) reads `dissolve` + `slide_wipe` — the xfade `fade` is a linear crossfade, NOT fade-through-black (luma 126 → 108 → 93 across the transition, no dip), so pixel-truth it IS a dissolve; the `fade` branch is validated on a separate true-fade fixture (luma 126 → 59 → 0 → 49 → 93). multi.mp4 flat dissolve reads `dissolve`; a true wipeleft fixture reads `slide_wipe` (revealed strips exactly 0.0, unrevealed 90–148). Two drift false positives were caught and fixed by the displacement + sharpness rules: a U2 overlay drift (50 px in 7 pairs) and speech1 shot 14 both read `slide_wipe` before the fix and correctly read `soft_unknown` after; U2 shot 3 keeps `slide_wipe` — verified as a real slide (11-pair run, dx +5…+19 eased, 106 px displacement, settles into the new layout at 5.08s). speech2 shot 12 `fade` is verified real (dense 30 fps sampling: luma dips to 20.9 at 18.37s with recovery both sides).
5. **Camera motion per shot (item 4) (`videodna/forensics.py`, `videodna/cli.py`)** — new per-shot fields `camera_motion` + `camera_motion_confidence` on the shot dict and both card builders (next to `motion_class`/`motion_energy`, rendered in the Motion line of each shot card; `unknown` is rendered with "(not classifiable from the burst — see v2.0.4 notes)"). Labels are `static` / `pan` / `unknown` only — **zoom and handheld are NOT shipped** (see Known remaining work). The classifier works on the existing per-shot burst lumas (≤ 12 frames at 12 fps, ~1 s, centred in shot) plus a supplementary burst for shots beyond the 32/24 sampling cap (`classify_camera_motion_for_shots()`, same burst + classifier, so coverage is the full shot list). **Static**: mean frame diff < 1.0 (the forensics static line), confidence 0.9. **Pan**: the (dx, dy) phase-correlation peak shift that `_planar_motion_coherence` previously threw away is now retained via a new `_phase_shift()` (which also corrects a pre-existing sign bug — the FFT peak is the NEGATED true shift; the old coherence value is untouched and no scoring rule changes). A pan needs ≥ 3 usable consecutive pairs (raw diff ≥ 0.8, coherence ≥ 0.4) with a dominant axis (median |shift| ≥ 1 px), ≥ 70% sign agreement within ±1 px of the median, orthogonal median ≤ 1 px, and mean coherence ≥ 0.5; confidence = the agreement fraction. Anything else — jitter, subject motion, textureless frames, multi-layer motion graphics — is `unknown` with confidence 0.0. Labelling only: no scoring behaviour changes. Measured: on the 9 videos, most shots are honestly `unknown` (U1 motion graphics, U3, speech1 34/34, speech2 15/15 — all have in-shot subject/overlay motion that masquerades as camera motion); `static` is asserted where it is real (U4, test.mp4, multi.mp4 both shots, M3 shots 2–3, U2 shot 4). No pan label fired on any of the 9 videos — a slow pan below the 1 s / 160 px noise floor stays `unknown`, which is the correct output.
6. **On-screen text / OCR (item 6) (`videodna/ocr.py` new, `videodna/cli.py`, `videodna/remake.py`, `videodna/report.py`)** — tesseract-ocr 5.3.4 + `tesseract-ocr-hin` installed from apt (system package, no pip dependency; `install.sh` untouched). `ffmpeg` has no OCR filter (checked). Per shot, the mid frame is extracted and piped to `tesseract` stdin (PSM 11, `-l eng+hin`, 1280 px max width, no upscale of smaller sources); text + word boxes (normalised 0–1000) land on the shot dict as `on_screen_text` / `on_screen_text_words` and on both card builders, replacing the old `OCR_TEXT_STATUS` ("text not extracted (no OCR available)") — shots with no text now read `"no text detected"`. OCR runs as CLI step "3c/5" after frame export. **Gating matters**: tesseract is confidently wrong on busy graphics (single garbage chars at conf 60–90), so confidence alone cannot gate. A word is kept only if TSV conf ≥ 70 AND it is an alphabetic word of length ≥ 3 (Latin or Devanagari, punctuation stripped) — or a digit token immediately following a kept word (so "Text 4" survives as a unit). Measured: U2 shot 3 reads "Text 4 Text 4"; speech2 shot 1 reads the real title/comment text ("cockroach Janata Party edit bnao Raifu bhai Replying") and shot 14 reads Hindi ("जनता"); speech1 shot 8 reads "EREN YEAGER". Single-word strays can still slip through ("Itkes", "wwe", "why", "like") — see Known remaining work. **The "BLOOD invisible" gap is narrowed, not closed**: 10 s of U2 frames at 1 fps across PSMs 3/6/7/8/11/12 plus grayscale/autocontrast/upscale preprocessing never read BLOOD (best fragment "BL:; 0 D") — the stylised display font is unreadable to tesseract 5.3.4. Runtime cost: ~3.4 s/shot at 1280 px eng+hin; speech2 OCR step 36.5 s (15 shots), speech1 95.1 s (34 shots); speech2 full analyze ~93 s → ~136 s. OCR degrades gracefully: if tesseract is absent or a decode fails, `extract_shot_text()` returns {} and cards fall back to the old status string.

### Known remaining work (not fixed in v2.0.4)

- **Zoom / handheld camera motion (not shipped, item 4)**: zoom was attempted and dropped — centre-vs-edge diff ratio does not separate (synthetic zoom 1.50 vs synthetic pan 1.89), and a centre-scale search residual is ≥ raw diff even on a clean synthetic zoom (resampling the high-frequency test pattern swamps the signal). Handheld was attempted and dropped — synthetic ±6 px random-walk jitter is invisible at 160×90 / 12 fps (all pairs shift (0,0), coherence 0.0). The `camera_motion` field exists and only ever emits `static` / `pan` / `unknown` today; a zoom/handheld classifier needs higher-resolution bursts or a different method.
- **`_planar_motion_coherence` sign bug (pre-existing, out of scope)**: the FFT phase-correlation peak is the NEGATED true shift — rolling an image by (dy=2, dx=3) peaks at (−3,−2); shifting by the raw peak gives coherence 0.0, by the negated peak gives 1.0. The new `_phase_shift()` in `forensics.py` negates the peak and returns the true shift; the old coherence value (which feeds scoring rules) was left untouched so no verdict changes. Fixing the old function itself would change verdicts and needs its own validation pass.
- **BLOOD still unread (item 6 gap, narrowed not closed)**: U2's giant BLOOD text is never read by tesseract 5.3.4 across PSMs 3/6/7/8/11/12 plus grayscale/autocontrast/upscale preprocessing (best fragment "BL:; 0 D") — the stylised display font is unreadable to it. The OCR gate (conf ≥ 70 + word len ≥ 3) also lets an occasional confident 3-letter misread through (speech2 shots 4 "like" and 9 "wwe" are single-word strays; speech1 shot 18 "why" is plausibly real but unverified), and OCR output has small width-dependent variance (speech2 shot 1 reads "…Replying cjo56" at 1280 px upscale but "…Replying" at native 1080 px — the gate drops the fragment either way at 1280 max width, no upscale). A better engine (e.g. an ML OCR) or a dictionary/whitelist pass would be needed to close these.
- **OCR cost + dependency (item 6)**: OCR adds ~3.4 s/shot (1280 px, eng+hin) — speech2 analyze ~93 s → ~136 s (OCR step 36.5 s), speech1 262 s total (OCR step 95.1 s). It needs the system packages `tesseract-ocr` + `tesseract-ocr-hin` installed (apt, no pip dependency); without them the pipeline falls back to the old "text not extracted" status. `install.sh` was NOT updated (off-limits for this change) — the next agent should add the apt install there.
- **Transition-label limits (item 3)**: a slide/push that spans a cut with a slow eased drift is still indistinguishable from a camera pan in some cases — the displacement (≥ half the frame width) and wipe-sharpness (revealed strip < 8 vs unrevealed > 40) rules reject the measured drifts, but a fast pan across a cut would still read `slide_wipe`. Transition duration is still not measured (only the cut instant). xfade `fade` is a linear crossfade, not fade-through-black — M3's first transition is pixel-truth `dissolve`, which may surprise anyone expecting the xfade name.
- **"ai_still" category (not added)**: speech2/speech1 contain AI still images, but the forensics has no `ai_still` label — AI stills currently spread across `ai_video`/`3d_render`/`static_zoom` in the mix. Adding it touches CATEGORIES, `_score_shot_metrics` rules, MODEL_CAPABILITIES in `remake.py`, `label_alias` in `fuse_review_probabilities`, and the review template — evaluate separately.
- **Speed**: the frame export adds one full decode pass — speech2 (21.3s, 1080p60) takes ~11.6s for the export on this VM (capped at 30 fps); full analyze went ~81s → ~93s. The decode itself is the floor (14.1s at native fps, 10.1s at 30 fps, measured with ffmpeg alone); reusing another pass's decode was not possible (visual.py seeks per frame; the guard samples at 160px/6fps).
- **apply-review + default template**: `agent_review.json`'s template annotations echo the tool's own per-shot calls, and fusion blends them 35% tool + 65% agent — so running apply-review with an UNFILLED template shifts the verdict slightly (speech2: analyze live 28% + 3d_render 18% vs fused live 29% + 3d_render 17%). Pre-existing v2.0.2 behaviour, not introduced here; a filled review is what the fusion is for.

## v2.0.3 — 2026-11-21

Audio classifier fix: real continuous speech no longer classified as `ambient_or_sfx`. Scope is the audio classifier only — no changes to shot detection, verdict logic, install.sh, doctor, or OCR.

### Bug

v2.0.2 classified a real 51.85s Hindi reaction/edit video (loud, −7.3 LUFS, full of continuous dialogue) as **ambient_or_sfx, BPM None**, even though the video is full of Hindi speech. (rea-video, run on the same file, correctly called it "voice + music".) This was the "Speech gate validation" known-work item from v2.0.2: the pause gate had only ever been validated in the negative direction (continuous music no longer called speech) because no real speech sample existed on the VM at the time.

### Root cause

In `_classify_audio_content` (`videodna/audio.py`), branch 1 (`speech_only`) required `speech_e >= 0.58` **and** a pause structure of `low_energy_frac >= 0.14` (or `dead_air_ratio >= 0.05`). The real speech sample — loud continuous fast speech with almost no gaps — measured:

- `speech_e` 0.5828 (only +0.0028 above the 0.58 gate — within re-encode noise)
- `low_energy_frac` 0.0950 (below the 0.14 pause gate)
- `dead_air` 0.0000, `bpm_conf` 0.11 (so branch 3's `bpm_conf >= 0.15` gate never fired either)

It failed branch 1 on the pause gate and fell through every later branch to `ambient_or_sfx`. Both gates were too strict for loud continuous speech with no gaps and no steady beat.

### Fix (two thresholds, branch 1 only)

| Threshold | Before | After |
|---|---|---|
| Pause gate (`low_energy_frac`) | `>= 0.14` | `>= 0.05` |
| Speech-band gate (`speech_e`) | `>= 0.58` | `>= 0.55` |

The `dead_air_ratio >= 0.05` alternative in branch 1 is unchanged. Nothing else in the classifier changed: branch 3's `bpm_conf >= 0.15` and its inner pause gate (0.05 / 0.02), branch 2, branch 4 (`music_only` bass `>= 0.25`), and the test_tone thresholds (dominant bin `>= 0.45`, flatness `< 0.005`) are exactly as they were. No new feature was added as a speech signal — spectral flatness was considered and rejected: beat120 (flatness 0.5998) breaks it globally.

### Why these values (measured margins)

- **speech1** (real Hindi dialogue, must become speech): speech_e 0.5828, low_energy_frac 0.0950, dead_air 0.0000, bpm_conf 0.11. After the fix it passes branch 1: pause margin +0.045 above 0.05, speech_e margin +0.033 above 0.55.
- **U4 music** (must stay non-speech): speech_e 0.5720, low_energy_frac 0.0053, dead_air 0.0000, bpm_conf 0.19. After the fix it still fails branch 1's pause gate (0.005 vs 0.05, margin 0.045 below) and branch 3's inner gate, so it stays **ambient_or_sfx** — unchanged from v2.0.2.
- The pause gate (0.05) is now the sole separator between speech1 (+0.045 above) and U4 (0.045 below) in branch 1 — symmetric margins, and 0.05 is the exact midpoint of the two known samples.
- **beat120** (flatness 0.5998, speech_e 0.5978) would pass the new speech_e test but is still blocked by the pause gate (0.000 vs 0.05). Clicks already exit via branch 1 (`dead_air` 0.95/0.87 or `low_energy` 0.76) and are unaffected.

### Before / after

| Sample | v2.0.2 | v2.0.3 |
|---|---|---|
| speech1 (real Hindi dialogue) | ambient_or_sfx, BPM None | **speech_only** |
| U4 (music, no speech) | ambient_or_sfx, BPM None | ambient_or_sfx, BPM None (unchanged) |

### Caveats (known, not fixed in this change)

- **Clicks remain misclassified as `speech_only`** (pre-existing behaviour, unchanged by this fix).
- **Threshold validated on two samples only** — one real-speech and one real-music sample exist. The 0.05 pause gate should be re-validated on more real samples before shipping: a music track with `low_energy_frac` slightly above 0.05 **and** `speech_e >= 0.55` would now be called `speech_only`.

## v2.0.2 — 2026-11-21

Seven verified weaknesses from the 2026-11-21 head-to-head (7 videos, tools-only) fixed and regression-tested. Test suite: **61 passed, 2 skipped** (the 2 skips are the pre-existing regression-video skips — template/style-B videos absent). All fixes verified end-to-end on the 7 test videos with the repo venv binary.

### Fixed

1. **Installer PATH/upgrade bug (`install.sh`)** — the shim lands in `~/.local/bin`, which is not on PATH on many systems, and an older `videodna` elsewhere on PATH shadows it, so after a "successful" install plain `videodna --version` still reported the old version. The old PATH warning only fired when `command -v videodna` failed, which never happens for upgraders. `install.sh` now detects an existing `videodna` on PATH outside `~/.local/bin` and prints a LOUD warning naming the path and detected version, stating it will shadow the new install, with three fixes (remove it, rename it, or put `~/.local/bin` first on PATH). It never silently overwrites a binary outside its own paths. Sandbox-tested both ways (warning fires with a fake old binary; no false warning without one).
2. **BPM octave fold (`videodna/audio.py`, `_estimate_bpm`)** — 180 BPM click trains read as 60.0 BPM (conf 0.91): the 3× period sat at the window's max-lag edge and out-scored the true period. The estimator now checks sub-multiples (lag/3, lag/2) and prefers the smallest lag whose autocorrelation is ≥70% of the peak, with parabolic interpolation around the chosen lag. Click trains now read 60.0 / 120.0 / **178.7** BPM. No regressions: sine tone still test_tone with BPM None; clicks in the full pipeline still get no BPM (speech_only suppression); beat120 still no BPM (onset conf 0.06 < 0.14 floor, documented).
3. **Motion-graphics shot over-segmentation (`videodna/shots.py`)** — big animated text/elements inside one shot were counted as soft transitions (U1 AutoAE promo: 4 shots for 1 continuous shot; U3 Zuckerberg/Meta: 3 for 2). New layout/background-continuity guard on frame-diff (soft) candidates only — hard cuts untouched: (a) candidates within 0.75s of start/end are suppressed (no settled before/after state); (b) changed-fraction rule comparing settled frames 0.75s before vs after (pixel change >25, threshold 0.45): below = same layout, suppress; above = keep. U1 is now **1 shot**, U3 **2 shots**. No regressions: M3 textured fade+slide stays 3 (both soft transitions kept), multi.mp4 stays 2, test.mp4 stays 1, U2 stays 4, U4 stays 1. Guard reports `detection.frame_diff_suppressed_by_guard` and fails open if frame-grabbing fails.

### Known remaining work (not fixed in v2.0.2)

- **OCR**: no tesseract/rapidocr/easyocr on this machine. Shot cards report the gap honestly; adding OCR means installing one of those and filling `on_screen_text` only from real extraction output.
- **Speech gate validation**: no real speech sample exists on this VM, so the pause gate is validated only in the negative direction (continuous music no longer called speech). A real speech / speech+bgm sample could still be affected if its pause ratio falls under 0.05 with dead air under 0.02. Also, the second classifier branch can still return `speech_plus_bgm` for continuous audio when `bpm_conf ≥ 0.25` or `bass ≥ 0.22` with `speech_e ≥ 0.45` — only the branch that fired for U4 was gated.
- **Shot-guard thin margin**: U2's 2.5s overlay scores 0.591 changed-fraction vs the 0.45 line. The guard is tuned on these 7 videos; a future motion-graphics video with a larger in-shot overlay (or a subtler real transition) could land near the line. The new regression tests pin all 7 counts so drift fails loudly.
- **PATH shadow still needs a human**: the installer now warns loudly, but the stale `/usr/local/bin/videodna` (v2.0.0) is still on this VM and still shadows the venv install for a plain `videodna` call. Removing/renaming it is a user decision. Note the existing test suite shells out to bare `videodna` in one test, so run the suite with `.venv/bin` first on PATH (`PATH="$PWD/.venv/bin:$PATH"`), otherwise that one test fails against the old binary — a live demonstration of the bug itself.
